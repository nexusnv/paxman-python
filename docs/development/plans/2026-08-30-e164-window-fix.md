# E.164 Scanner Bounded Window Fix Implementation Plan (issue #65)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix E.164 scanner bounded window 32 being too tight for spaced numbers — raise `_E164_MAX_WINDOW` to cover worst-case separator expansion and ensure spaced 15-digit numbers are recognized with correct spans.

**Architecture:** Increase `paxman/capabilities/Phone/grammar/e164_recognition.py:_E164_MAX_WINDOW` from 32 to 64 (covers 15 digits + 14 gaps × 3 chars worst-case " - " + leading "+" = 58 with margin; 2-char gaps = 44). Keep `ScannerMatcher.max_window` declarative enforcement (miss on overflow) — window is enforced by the matcher, not by capping the scan. The `max_window` remains data (ADR-0009 §9.3). Tests pin spaced E.164 with 2-char (44) and 3-char (58) separators.

**Tech Stack:** Python 3.11+, pytest (unit/capability markers), strict pyright, ruff, import-linter, uv.

**References:** Issue #65, `paxman/capabilities/Phone/grammar/e164_recognition.py:32-38`, `paxman/core/grammar/matchers/scanner.py:84-88` (max_window enforcement), `tests/capabilities/phone/test_grammar.py`.

```python
def test_spaced_15_digit_with_two_char_separators(self) -> None:
    """(#65) 15-digit spaced with 2-char gaps must not be truncated."""
    # 2-char gaps: " -" (space+dash) => 15 digits +14*2 +1 =44
    spaced2 = "+" + " -".join("123456789012345")
    assert len(spaced2) == 44
    results = self.grammar.recognize(spaced2)
    assert len(results) == 1
    assert results[0].start == 0
    assert results[0].end == 44
    assert results[0].raw_text == spaced2
    assert results[0].notation.value == "123456789012345"

def test_spaced_15_digit_with_three_char_separators(self) -> None:
    """(#65) 15-digit with 3-char gaps must not be truncated."""
    # 3-char gaps: " - " (space+dash+space) => 15+14*3+1 =58
    spaced3 = "+" + " - ".join("123456789012345")
    assert len(spaced3) == 58
    results = self.grammar.recognize(spaced3)
    assert len(results) == 1
    assert results[0].start == 0
    assert results[0].end == 58
    assert results[0].raw_text == spaced3
    assert results[0].notation.value == "123456789012345"
```

- [ ] **Step 1: Update `_E164_MAX_WINDOW` to 64**

Replace:

```python
# Char window carrying the 15-digit bound as data; separators inflate raw
# length beyond the digit count, so the char window is larger than 15 to
# hold a full 15-digit number with separators and the leading "+". 32
# safely covers "+x (xxx) xxx-xxxx" plus the runaway-trim case
```

with:

```python
# Char window carrying the 15-digit bound as data; separators inflate raw
# length beyond the digit count, so the char window must hold a full
# 15-digit number with separators and the leading "+". Worst case:
# 15 digits + 14 gaps ×3 (" - " space-dash-space) + "+" = 58 chars,
# e.g. "+1 - 2 - 3 - 4 - 5 - 6 - 7 - 8 - 9 - 0 - 1 - 2 - 3 - 4 - 5".
# 64 safely covers that plus the runaway-trim case
# "+15551234567 5551234567" (23 chars) and the oversized first-run case
# "+12345678901234567890" (21 chars) while still bounding the scanner.
# See #65.
_E164_MAX_WINDOW = 64
```

Keep the import of `ScannerMatcher` unchanged; the matcher already carries `max_window=_E164_MAX_WINDOW`.

- [ ] **Step 3: No scan cap needed — window is enforced declaratively**

Keep `ScannerMatcher` enforcement as is (miss on overflow). Do NOT add a `j = min(j, pos+max_window)` clamp in `_e164_scan`; clamp vs miss are different semantics (miss advances `pos+1`, clamp would emit a truncated span). The window is data; the matcher enforces it. Add a comment in `_e164_scan` docstring noting the window is enforced declaratively by `ScannerMatcher` (no core change).
