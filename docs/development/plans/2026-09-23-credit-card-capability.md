### Design decisions (locked, from research §13 + §16)

1. Canonical default `pan` = compact contiguous 12–19 ASCII digits; offered `{"grouped"}` = grouping-agnostic re-chunk, groups of 4 from the left, last group takes the remainder (16→`4111 1111 1111 1111`, 15→`3782 8224 6310 005`, 14→`3605 0234 1969 08`, 19→4-4-4-4-3). ADR-0011 class **encoding**, declared in one contract-docstring paragraph naming both `grouped` and `encoding` (test scan requirement). Input grouping is grouping-agnostic (4-6-5 input recognized); output never renders brand 4-6-5 — research §6.1 table's `3782 822463 10005` example is the deferred brand-faithful option, not v1.
2. Notation `PANNotation(digits: str, compact: str)`, `@dataclass(frozen=True, slots=True)`; `compact == digits` always; equality re-checked by the structure rule as defense-in-depth (ISIN precedent). No IIN/MII/length facets — 6-vs-8 IIN is interpretation, not identity (research §3/§5.4).
3. One grammar `pan_recognition` (`semantics = "pan_recognition"`, `single_value = True`), kernel `ScannerMatcher(scan=…, boundary=BoundarySpec.WORD, emit=…)`; class body declares only `name`/`semantics`/`single_value`/`matchers` (stage fields stay `None` — dead on the matchers path, `pipeline.py:36-41`). Four guards verbatim from research §4.2: word guards, date guard `(?!\s\d+/)` per repetition, joined-run orphan guard `(?!(?:[ \t\-]?\d){1,11}(?![0-9/]))`, scan-time left joined-run guard (1–11 soft-joined digits before the claim start → refuse; Python `re` forbids variable-width lookbehind). Label branch requires mandatory `[\s:-]+` (glued `PAN4111…` → MISSING); digit filter lives only in `_pan_scan`/`_pan_emit` (scanner discards the scan payload, `scanner.py:91`). Whole soft-joined run is claimed atomically from its origin: `order 12 4111111111111111` → 18-claim `INVALID`, line break is a hard boundary → `SUCCESS` (documented trade-off, §8 #25).
4. Length 12–19 everywhere. Dispositions: irregular whitespace (double-space/tab) → documented `MISSING` non-recognition (§2.1 row 8, §13 #9); dot/underscore/slash separators → DEFER to community `extra_grammars`; masked/truncated/token/OCR/8–11-digit → `MISSING` never `INVALID`; expiry-attached → PAN-span-only `SUCCESS` (§8 #13); 20+ runs (compact/spaced/hyphen/expiry-fused) → `MISSING` with no 16-carve (§8 #7/#18/#19/#14).
5. Two rules, one `target_semantics = frozenset({"pan_recognition"})`: PARSER `Section 5-pan-structure-luhn` (authority `ISO/IEC`, `ISO/IEC 7812-1:2017`, `https://www.iso.org/standard/70484.html`, version `2017`, `kind="specification"`, `lifecycle="active"`, `publication_year=2017`) always active — local `_PAN_RE = ^[0-9]{12,19}$` + local Luhn helper (copy the ISIN/IBAN accumulator shape, never import); LOOKUP_TABLE `Section 1-brand-prefix-membership` (authority `Brand networks`, `kind="registry"`, wiki reference, `version="Rolling 2026"`) gated `requires_features = frozenset({"include_brand_validation"})` against the contract field default `False` (GTIN `include_verified` precedent; engine evaluates conjunctively at `orchestrator.py:534-546` — a falsy/missing field drops the rule). The brand rule re-runs Luhn as intentional ADR-0012 corroboration: it returns the same verdict as the ISO rule and **never waives it** — no braintree UnionPay bypass (§13 #12): a Luhn-invalid UnionPay fails both rules → `INVALID` under every contract.
6. Brand data `rules/data/brand_prefix.py` seeded exactly from research §7.2's eight brands (visa, mastercard, american-express, discover, diners-club, jcb, china-unionpay, maestro) as `(prefix intervals, allowed lengths)` tuples parallel to `GTIN/rules/data/gs1_prefix.py`; header states SECONDARY-never-ISO, the refresh procedure, and that the §7.2 "Others" row (Mir/RuPay/Troy/UATP) is deliberately deferred — absent from the allowlist means generic-valid off-gate, brand-invalid on-gate.
7. Resolution split (§7.3/§9): default contract drops the brand rule → Luhn-valid unknown-prefix → `SUCCESS`; `include_brand_validation=True` + unmatched prefix → `INVALID`; two distinct PANs in one slice → `MultipleMentionsError` (`single_value=True`), spaced/compact/dashed twins of the same digits coalesce to `SUCCESS`; UnionPay-shape Luhn-valid → `SUCCESS` either way. `masked`/`truncated`/`brand` are never formats.
8. Fixture hygiene (§12): public test numbers only (`4111111111111111`, `5555555555554444`, `378282246310005`, `371449635398431`, `6011111111111117`, `3530111333300000`, `36050234196908`, `36227206271667`, `4222222222222`, `4716221051885662`, `4929722653797141`); the 8-/11-digit Luhn references (`79927398713`, `17893729974`, `48721484`) are Luhn-helper-only fixtures below the floor — they must fail `matches()`'s length gate and are never recognition fixtures; invalid pins `4111111111111112`, `5398228707871528`.
