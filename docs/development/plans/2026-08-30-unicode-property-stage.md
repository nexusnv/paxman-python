# UnicodePropertyStage — Build-Time Range Generator Implementation Plan (issue #51)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a build-time Unicode property range generator and a thin `UnicodePropertyStage` so grammars can recognize `\p{Sc}`, `Script=Han`, etc., via vendored ranges without runtime `regex` dependency — pilot with SI `°µΩÅ` hand-table parity and Language Han.

**Architecture:** New tool `tools/regenerate_unicode_property_data.py` reads vendored `paxman/shared_data/unicode_snapshot.json` (source URL + Unicode version + ranges for `Sc` and `Han`) and writes `paxman/core/grammar/data/unicode_ranges.py` with pure frozen tables `SC_RANGES`, `HAN_RANGES`, `UNICODE_VERSION` (same pattern as `regenerate_isbn_range_data.py` — deterministic, no network in CI). `UnicodePropertyStage` is a thin alias over `RegexStage` (frozen, slots, compiled once) that consumes the generated table — opt-in per grammar, no `regex` module at runtime. Parity test ensures generated range ↔ hand lexicon for SI symbols.

**Tech Stack:** Python 3.11+, `uv`, `ruff`, strict `pyright`, `import-linter`, `pytest` (unit/property), `pathlib`/`argparse` for generator, `re` for range compilation.

**References:** Issue #51, Study §3.4, `HOW_TO:282` Unicode-property row, `tools/regenerate_isbn_range_data.py`, `tools/regenerate_si_prefix_data.py` (deterministic header + `--check`), `paxman/capabilities/SIUnit/grammar/symbol_recognition.py` (hand `°µΩÅ`), `paxman/capabilities/SIUnit/grammar/data/unit_symbol_tokens.py` (hand table).

- [ ] **Step 2: Implement `UnicodePropertyStage`**

Create `paxman/core/grammar/stages/unicode_property.py` as thin alias over `RegexStage` (follow `paxman/core/grammar/stages/regex.py` and `lexicon.py` pattern: `@dataclass(frozen=True, slots=True)`, `field(init=False)` for compiled pattern, `Stage` protocol with `run(state)` if needed, but simplest is to inherit from `RegexStage`):

```python
"""UnicodePropertyStage — build-time range stage for \\p{...}."""

from __future__ import annotations

import re
from dataclasses import dataclass, field

from paxman.core.grammar.stages.regex import RegexStage

@dataclass(frozen=True, slots=True)
class UnicodePropertyStage:
    """Thin alias over RegexStage with generated Unicode ranges.

    Compiles a character class once from the vendored
    `unicode_ranges.py` table. No `regex` module at runtime.
    Opt-in per grammar; over-broad `\\p{Emoji}` remains too broad per
    precedent and is not exposed.
    """

    property: str
    ranges: tuple[tuple[int, int], ...]
    _regex: re.Pattern[str] = field(init=False, repr=False)

    def __post_init__(self) -> None:
        # Build regex class correctly: use chr() to materialize char,
        # not f"\\u{start:04X}" which would be double-escaped.
        # For supplementary, use chr() directly and let re handle it.
        parts: list[str] = []
        for start, end in self.ranges:
            if start == end:
                parts.append(re.escape(chr(start)))
            else:
                parts.append(f"{re.escape(chr(start))}-{re.escape(chr(end))}")
        pattern = f"[{''.join(parts)}]"
        # For supplementary Han, re handles surrogate pairs in Python 3.11+ (PEP 393)
        object.__setattr__(self, "_regex", re.compile(pattern))

    def matches(self, ch: str) -> bool:
        """Return True if single char `ch` is in the property."""
        return bool(self._regex.match(ch))

    # For PipelineGrammar integration, expose as stage with `run` if needed
    # or provide helper to get pattern for RegexStage delegation.
```

Ensure `slots=True` and `field(init=False)` for `_regex`, and `object.__setattr__` is valid for frozen slots (as in `RegexStage` precedent). Alternatively, make it inherit from `RegexStage` and pass generated pattern to super, but the above matches `LexiconStage`/`RegexStage` style.

Add export in `paxman/core/grammar/__init__.py`:

```python
def test_si_hand_table_vs_sc_parity():
    """SI hand table for °µΩÅ must not be confused with Sc."""
    from paxman.capabilities.SIUnit.grammar.data.unit_symbol_tokens import SYMBOL_TOKENS
    from paxman.core.grammar.data.unicode_ranges import SC_RANGES

    # Build Sc set from ranges (full, not BMP-filtered)
    sc_set = {chr(cp) for start, end in SC_RANGES for cp in range(start, end+1)}
    # SI symbols °, µ, Ω, Å are in hand table but must not be in Sc
    for sym in ["°", "µ", "Ω", "Å"]:
        assert sym in SYMBOL_TOKENS, f"{sym!r} missing from SI hand table"
        assert sym not in sc_set, f"{sym!r} should not be in Sc (Currency_Symbol)"

def test_han_vs_latin_parity():
    """Han property must be distinct from Latin hand table."""
    from paxman.core.grammar.data.unicode_ranges import HAN_RANGES

    han_set = {chr(cp) for start, end in HAN_RANGES for cp in range(start, end+1) if cp <= 0xFFFF}
    assert "中" in han_set or any(0x4E00 <= ord("中") <= 0x9FFF for _ in [1])
    # More direct: check via stage
    from paxman.core.grammar.stages.unicode_property import UnicodePropertyStage
    han_stage = UnicodePropertyStage(property="Han", ranges=HAN_RANGES)
    assert han_stage.matches("中")
    assert not han_stage.matches("A")
    assert not han_stage.matches("°")
```
