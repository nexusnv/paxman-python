# DOI Parameterized UX Sweep (2026-09-18)

Black-box acceptance for the new `doi` capability through the public API
only (`register_all_shipped()` + `canonicalize()`), per the
paxman-parameterized-testing skill. Expectations were derived from
`docs/development/research/2026-09-18-doi-canonicalization.md`
(§2.1 inventory, §2.2 wild rows, §8 edge cases, §9 resolution map) —
never from observed runs. No `paxman/`, `tests/`, or config file was
touched; disposable scripts/data removed after the run (method + seed
below regenerate everything).

## Method

- Seed `20260918`; 108 rows (100 `assert`, 8 `explore`).
- ~55 clean: every §2.1 RECOGNIZE form, case variants, 17 seeded random
  shapes (4–9-digit registrants, dotted tails, `%2F` alphabet), 8 sibling-
  domain MISSING probes (ISBN/ISSN/Phone/Date/URL/Email/UUID/bare prefix).
- ~45 garbage: empty/whitespace/prose, glued runs, truncated shapes,
  shortDOI, over-long registrants, URN-colon DEFER, inner whitespace,
  quoteless breaks, fullwidth lookalikes, multi-mention triples.
- Contracts: `default`, `url`, `year2020` (drops the 2025 rule),
  `suppress` (`suppress_common_words=True`), `badfmt`
  (`output_format="upper"` → `ContractError` at factory).
- Derivation rules under test: `url` keeps status, renders
  `https://doi.org/<bare>` on SUCCESS; `year2020` flips SUCCESS→INVALID,
  keeps MISSING; `suppress` ≡ default row-for-row.

## Findings

### F1 — Quoteless breaks truncate, not void (expectation correction)
`10.1038/a"b`, `10.1038/a'b`, `10.1038/a&b` resolve SUCCESS with the
leading fragment (`10.1038/a`), exactly like the whitespace row
(`10.1038/a b` → `10.1038/a`). Initial sweep rows expected MISSING;
the observed behavior is correct per the Wikidata P8966 consensus the
spec adopts (`(?:(?![\"&'])\S)+` matches up to the quote — verbatim the
same mechanism). Rows corrected, board green. No code change.

### F2 — year-filtered multi-mention reads INVALID, not MultipleMentionsError
Under `year=2020` (all rules dropped), two-distinct-DOI input returns
INVALID instead of raising. Engine precedence, DOI-independent: with no
surviving validation rules there are no valid candidates to be ambiguous
between, so multiplicity never materializes. Defensible UX (raising
about ambiguity between two values neither of which validates would be
worse); derivation rule recorded in the sweep harness. No code change.
Worth a one-line note in the engine docs if this precedence is relied
on elsewhere — left as an observation, not an issue.

### F3 — Degraded carriers still resolve (observations, all sane)
`https://dx.doi.org:443/10.1038/x` (port breaks the host group) and
`mailto:10.1038/x` both resolve SUCCESS with the bare core. Graceful
degradation, consistent with the opaque-suffix model. No action.

### F4 — Graphic-type tension confirmed open (explore, no action)
`10.1038/a\u200bb` (ZWSP) and `10.1038/a\u200fb` (RTL mark) resolve
SUCCESS with the invisible char preserved — the known thermo-nuclear
LOW note (Handbook §4.3.1 Graphic-type vs `\S`). Left open as a
follow-up decision (rule-level `unicodedata` rejection → INVALID);
deliberately not asserted either way here to avoid laundering.

### F5 — Fold boundary and terminal punctuation behave (explore, all sane)
`Á` preserved while `N` folds (`10.1038/Né` → `10.1038/né`); trailing
`?`/`;`/space excluded; `doi:` with blank core MISSING. Matches the
PDF-confirmed case rule. No action.
